Lullabyte architecture on Cloudflare

Revision 2, 2026-11-08. One Workflow per story. Every stage output is a versioned row in D1. People review at three gates. Source of truth: integration/architecture.md.

What is decided

Workers PaidFree gives 10 ms CPU per invocation and 50 external subrequests. One story needs more.
UUID v7 for every IDstory_id included. A date is an attribute, never an ID. The schema enforces it.
Scout runs aloneCron starts Scout only. Its news items wait in D1 until someone selects one.

Flow

Decisions

#DecisionWhy
D1Workers Paid. Free is for a demo only.CPU and subrequest limits on Free (see the limits table).
D2Scout is its own cron job. It writes news items and stops.Scout can run, fail, or re-run without touching any story.
D3One Workflow instance per story; the instance ID is the story ID.The platform retries and checkpoints each step. A crash resumes at the failed step.
D4Each stage output is an artifact row in D1. Steps pass IDs, not content.D1 rows do not expire. Workflow state is kept 7 to 30 days after the instance ends.
D5Human gates are waitForEvent with an explicit timeout.A waiting instance does not count toward the concurrency limit.
D6The front end reads one immutable, versioned story package.A published story never changes under a reader.
D7UUID v7 for every ID. Decided.Time-ordered and unique across stages.
D8No Queues and no KV in the first release.The Workflow gives retry and ordering. Status is a D1 column.

Retries: generation_id = instance ID + step name + loop round. A retry reuses it, so the insert does nothing and the step reads the first row. A regeneration is a new round, so it gets a new version even with the same inputs.
