# S2 results: scene premise test on 3 real news texts

Issue #26. Scenario RUN-06.S1. Fixtures for RUN-06.S2.

## Verdict

**Pass.** All 3 `script` steps succeeded. 20 of 21 pages passed validation
and layout with at most one repair: `20/21 = 0.952`. The target is 0.90.

The first-try rate is low: `6/21 = 0.286`. Most failed first scene attempts
have one cause, `primitive_renderer`: a rig-only primitive on a raster asset
(see "Issue codes"). Finding: #63.

## Scope of this run

- This run is the **pre-backdrop baseline** of the script, scene and TTS
  premise (planner decision, 2026-11-19, comment on #26).
- ADR 0016 (`main` `3d6ef6c`) adds a required scene `backdrop`. This branch
  does not have it. The run used the code at `91973ec`, which is based on
  `origin/main` `1e54725`. ADR 0016 changed only documents.
- After the run, the branch was rebased onto `origin/main` `0fc6fda` so that
  it can merge. Between `1e54725` and `0fc6fda`, `main` changed documents and
  the S1 spike (`apps/storybook/src/spike/`, `apps/storybook/scripts/`), and
  nothing in `packages/` or `apps/storybook/worker/`. `91973ec` is the
  pre-rebase commit; after the rebase the same change is `dd932c1`. RUN-06.S2
  passes on the rebased code.
- The choice of backdrop is tested later, in a new S2 run on three new texts,
  after the backdrop code issues land.

### Supplement: recomputed issues of all failed attempts

To show why the repairs happened, the issues of every failed attempt were
**recomputed** from the stored answers in `call_log.result` (implementation
decision). Each stored `script` and `scene` answer of the run goes through
the same checks, in the same order, as
`apps/storybook/worker/workflow/steps/scene.ts` `checkScene` and
`steps/script.ts` `checkScript` at `91973ec`. The script is
`apps/storybook/scripts/s2/analyze.ts`. It prints only counts, one JSON line
per run. To reproduce the tables below, run it on the six rows files that
`s2-run.ts` saved before it wrote the fixtures:

```bash
pnpm --filter @storybook/app exec tsx scripts/s2/analyze.ts \
  .s2/rows-s2-1-2026-11-20T00-01-41-358Z.json \
  .s2/rows-s2-2-2026-11-20T00-01-41-358Z.json \
  .s2/rows-s2-3-2026-11-20T00-01-41-358Z.json \
  .s2/rows-s2-1-2026-11-20T00-09-07-554Z.json \
  .s2/rows-s2-2-2026-11-20T00-09-07-554Z.json \
  .s2/rows-s2-3-2026-11-20T00-09-07-554Z.json
```

The first three files are the primary pass, the last three the comparison
pass.

**The input rows are not tracked; this supplement is reproducible only from
the local `.s2` evidence of the run.** The rows files hold full model
outputs, so they are not committed. After the merge they are kept outside
git, in `~/.claude/worktrees/cmu/s2-evidence-2026-11-20/`. The
`codes` field gives the "attempts" columns, `raw` the "issues" columns and
`detail` the primitive table.

Cross-check: for each of the 6 runs, the recomputed results match the stored
outcome exactly. The number of failed first attempts equals the number of
repaired pages. The number of failed repairs equals the `needs_review`
count. The code of the stored `needs_review` revision (`layout.bounds`) also
matches.

"Attempts" counts each failed attempt once per code. "Issues" counts every
issue.
